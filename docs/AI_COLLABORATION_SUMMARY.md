# 🤖 AI 協同開發歷程摘要 (AI Collaboration Summary)

**專題題目**：D&D 5E 劇情導向非典型 NPC 智慧生成系統 *(TRPG Story-Driven Unorthodox NPC Generator)*  
**開發環境**：Python 3.12（純標準函式庫，零外部依賴，支援跨平台與 Windows UTF-8）  
**協同對象**：人類開發者 (User / DM) × Google DeepMind Antigravity AI 系統  
**交付連結**：[https://github.com/41154B003Sam/dnd-5e-npc-generator](https://github.com/41154B003Sam/dnd-5e-npc-generator)

## 📌 一、 專題緣起與核心痛點定位

在 TRPG（桌上角色扮演遊戲，以《龍與地下城》D&D 5E 為核心體系）的跑團實務中，地下城主（DM / Storyteller）經常面臨龐大的備戰壓力：
1. **傳統工具僵化**：現有的開卡工具（如 D&D Beyond、5eTools 等）多為玩家角色（PC）設計，強制遵循嚴格的配點、負重、裝備限制與技能套路，無法快速產出符合劇情情境的非玩家角色（NPC）。
2. **缺乏故事溫度與非典型特色**：傳統產生的戰士千篇一律是全身板甲配長劍；法師必定手持魔杖或法杖。然而在精彩的劇本中，往往需要「表面是平凡老農、隨身拿著草耙，真實身分卻是退隱禁衛隊長的戰士」，或是「不拿常規法器、而是叼著刻印符文的石楠木老煙斗吞吐青煙施法的大魔導師」。
3. **規則限制玩家，而非約束 DM**：使用者明確指出，規則書主要是用來維護玩家間的公平與平衡，但 NPC 是 DM 鋪陳劇情與情緒的資產，應當具備更高的敘事自由度與非傳統彈性。
4. **多頁試算表翻找不易**：大型 Excel 角色卡往往包含 10~19 個工作表，DM 在戰鬥與對話的緊張節奏下，需要的是「垂直排列、一眼掃視全局」的直向卡片。

基於上述洞察，雙方共同確立了專題目標：**打造一套「故事敘事導向、數值與身分解耦、支援非典型裝備法器、具備靈活 4d6dl1 屬性建議，並具備雙平台圖形化介面」的 TRPG NPC 專用智慧生成引擎。**

## 🔄 二、 人機深度對話與架構演進歷程 (六大關鍵轉折)

本專案經過了數輪深度對話、批判性審查與敏捷迭代，每一次架構進化皆由人類使用者的精準批判所驅動：

### 階段 1：釐清核心需求與真隨機骰點機制
- **使用者提出**：
  - 需要真實骰子（4d6 drop lowest 1，即擲 4 顆六面骰，捨去最低點數）。
  - 隨機生成種族、背景、職業、年齡、信仰、語言，並能與使用者輸入的劇情脈絡高度融合。
  - 具備自由輸入關鍵字的功能，生成非傳統特長與生活裝備。

### 階段 2：關鍵批判與架構轉折（使用者回饋驅動）
- **轉折點 A：屬性點數不應硬編碼，改為「建議配置」與「種族加值候選清單」**
  - *使用者糾正*：「屬性點數不需要直接寫死在卡片上。我們提供建議配置即可，種族加值也是列出可提升的清單，讓 DM 在需要時自主挑選，保留彈性。」
  - *AI 實作*：將屬性模組重構為「原始擲骰池（6 組 4d6dl1 明細）」+「職業最優建議配置（優先權建議）」+「獨立列出可選種族加值」，維持純粹建議性，不剝奪玩家與 DM 決策權。
- **轉折點 B：非典型特長應支援「無」，隨心生成常規凡人**
  - *使用者糾正*：「不是每個角色都需要獨特異能，有時候我只想生成普通的農夫或商人。關鍵字輸入功能很好，但預設應該要是『無』。」
  - *AI 實作*：重構特質引擎，預設生成平民凡人（無超常異能）；當使用者輸入「火焰」、「霜凍」、「靈魂」等關鍵字時，才動態賦予相應的特質與規則效果。
- **轉折點 C：等級關鍵字解析與特殊狀態（被封印的大魔導師）**
  - *使用者提出*：「角色等級需要能自由輸入關鍵字，例如『大魔導師』必然有 12~16 等；甚至支援進階客製，例如『被封印的大魔導師』，等級在但部分法術環位遭到封印限制。」
  - *AI 實作*：開發自然語言等級解析器，將「老兵」對應至 Lv.5、「大魔導師」對應至 Lv.13~14，並在識別出「封印 / 詛咒」時，自動標記高環法術位限制警示與 CR 戰力下修評估。
- **轉折點 D：非典型武器與生活化法器（草耙與老煙斗）**
  - *使用者回饋*：「如果我是農夫但戰鬥定位是戰士，武器可能是長草耙；法師可能不用魔杖，而是抽煙斗施法。」
  - *AI 實作*：建立「非典型敘事武器庫」與「故事奧術法器庫」，在戰鬥數據上精確映射至 D&D 5E 規則傷害骰（長草耙對應 1d8/1d10 多用武器、老煙斗對應專注法器），完美實現「故事外貌生活化，戰鬥數值規格化」。

### 階段 3：從命令列進化到雙重零門檻圖形介面 (GUI & Web)
- **使用者回饋**：「需要開啟終端機來執行，對我來說不夠友善。」
- **AI 實作**：
  - 開發 **原生桌面視窗版 ([`gui.py`](gui.py))**：以 Python 內建 `tkinter` 打造現代暗黑高對比介面，完全免開黑窗。
  - 開發 **免安裝網頁版 ([`index.html`](index.html))**：支援直接以瀏覽器開啟離線執行，具備即時預覽、隨機篩選與專屬列印/存為 PDF 樣式。
  - 打造超輕量本機伺服器 ([`server.py`](server.py))：一鍵自動在預設瀏覽器中開啟介面。

### 階段 4：專案獨立拆分與資安合規
- **使用者要求**：「為什麼這個 repository 附在別的專案？應該要分開建立獨立 repository。」
- **AI 實作**：
  - 建立專屬獨立 GitHub 倉庫 `https://github.com/41154B003Sam/dnd-5e-npc-generator`。
  - 遵循資安規範：絕無任何 API Key、存取金鑰或 Web App 執行網址；repo 名稱與程式碼中不含學號或個人姓名。

### 階段 5：Windows 批次檔實機除錯 (CRLF vs LF & CP950)
- **使用者提出**：「點了 .bat 檔無法執行，甚至出現『命令語法不正確』直接閃退。」
- **問題診斷與修復**：
  - 排查 Windows `cmd.exe` 在繁體中文預設代碼頁 CP950 下，解析包含 `if (...)` 的多行區塊時，因 Unix LF 換行符號引發的語法錯誤。
  - 修復 `echo ... D&D 5E ...` 中 `&` 未轉義導致指令中斷的問題。
  - 加入智慧跨目錄自動搜尋機制（即使將 `.bat` 檔單獨下載到「下載」資料夾，也能自動定位主程式目錄）。

### 階段 6：Excel 模板回填實驗、架構反思與最終回歸核心
- **使用者提出**：「回填 Excel 模板導致格式損毀、許多下拉選單壞掉、部分圖片遺失。我決定放棄填入 Excel，因為破壞公式的問題無法根本解決。原本的網頁與應用程式版本已經相當優秀，回歸生成器本身。」
- **架構決策與終端收斂**：
  - 深度反思：第三方試算表解析庫在處理包含多達 19 個工作表、大量 VML 向量繪圖、資料驗證下拉選單與巢狀跨表公式時，極易因底層規範不相容而產生不可逆損毀。
  - **回歸跑團的核心痛點**：DM 真正需要的是**「直向快速掃視角色卡 (Vertical Quick-Scan)」**與**「無損通用的輕量資料交換格式 (Markdown/CSV/JSON)」**。
  - 全面清理冗餘的大型模板與脆弱代碼，讓專案維持 **100% 穩定、秒速執行、零外部相依性** 的高質量交付標準。

## 🛠️ 三、 技術實作亮點與除錯彙整

| 工程挑戰 | 根本原因 | 具體解決方案 |
| :--- | :--- | :--- |
| **Windows 終端 Emoji 編碼錯誤** | Windows 預設 CP950 編碼無法輸出 UTF-8 Emoji (📜, 🎲) | 在 CLI 入口加入 `sys.stdout.reconfigure(encoding="utf-8", errors="replace")`。 |
| **批次檔閃退與命令語法不正確** | Unix LF 換行破壞 cmd 解析器；`&` 符號未轉義 | 強制批次檔使用 CRLF 換行，轉義 `D^&D 5E`，並加入 `pause` 與路徑回退機制。 |
| **零相依性離線環境** | 大型套件於受限環境容易缺失 | 捨棄非必要第三方套件，全系統純以 Python 3 標準函式庫開發。 |
| **跑團主持資訊過載** | 傳統試算表橫向維度過大、翻頁繁瑣 | 設計 Markdown 直向排版，以高對比卡片在 3 秒內提供戰鬥與社交關鍵情報。 |
