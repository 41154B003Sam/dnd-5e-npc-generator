# 🤖 AI 協同開發歷程摘要 (AI Collaboration Summary)

**專題題目**：D&D 5E 劇情導向非典型 NPC 智慧生成系統 (TRPG Story-Driven Unorthodox NPC Generator)  
**開發環境**：Python 3.12 (純標準函式庫，零外部依賴，支援跨平台與 Windows UTF-8)  
**協同對象**：開發者 (User / DM) × Google DeepMind Antigravity AI  

---

## 📌 一、 專題緣起與核心痛點定位

在 TRPG（桌上角色扮演遊戲，以《龍與地下城》D&D 5E 為核心）的跑團實務中，地下城主（DM / Storyteller）經常面臨龐大的備戰壓力：
1. **傳統工具僵化**：現有的開卡工具（如 D&D Beyond、5eTools 等）多為玩家角色（PC）設計，強制遵循嚴格的配點、負重、裝備限制與技能套路，無法快速產出符合劇情情境的非玩家角色（NPC）。
2. **缺乏故事溫度與非典型特色**：傳統產生的戰士千篇一律是全身板甲配長劍；法師必定手持魔杖或法杖。然而在精彩的劇本中，往往需要「表面是平凡老農、隨身拿著草耙，真實身分卻是退隱禁衛隊長的戰士」，或是「不拿常規法器、而是叼著刻印符文的石楠木老煙斗吞吐青煙施法的大魔導師」。
3. **規則限制玩家，而非約束 DM**：使用者明確指出，規則書主要是用來維護玩家間的公平與平衡，但 NPC 是 DM 鋪陳劇情與情緒的工具，應當具備更高的敘事自由度與非傳統彈性。

基於上述洞察，雙方共同確立了專題目標：**打造一套「故事敘事導向、數值與身分解耦、支援非典型裝備法器、並具備靈活 4d6dl1 屬性建議」的 TRPG NPC 專用生成引擎。**

## 🔄 二、 人機對話互動與架構演進歷程

本專題的架構並非一蹴可幾，而是經過了數輪深度對話、批判性審查與設計迭代：

### 階段 1：釐清核心需求與生成邏輯
- **使用者提出**：
  - 需要真實骰子（4d6 drop lowest 1，即擲 4 顆六面骰，捨去最低點數）。
  - 隨機生成種族、背景、職業、年齡、信仰、語言，並能與使用者輸入的劇情脈絡高度融合。
  - 具備非傳統獨特異能機制（如天生親和火焰、獲得額外抗性等）。
  - 未來需對接客製化 Excel 角色卡模板。
- **AI 初步提案**：
  - 設計硬編碼的屬性直接指派演算法與預設角色卡欄位。

### 階段 2：關鍵批判與設計轉折（使用者回饋驅動）
- **轉折點 A：屬性點數不應寫死，改為提供「建議配置」與「種族加值候選清單」**
  - *使用者糾正*：「屬性點數不需要直接寫死在卡片上。我們提供建議配置即可，種族加值也是列出可提升的清單，讓 DM 在需要時自主挑選，保留彈性。」
  - *AI 實作*：將屬性模組重構為「原始擲骰池（6 組 4d6dl1 明細）」+「職業最優建議配置（優先權建議）」+「獨立列出可選種族加值」，維持純粹建議性，不剝奪玩家與 DM 決策權。
- **轉折點 B：獨特異能應預設為「無」，僅在指定關鍵字時注入**
  - *使用者糾正*：「不是每個角色都需要獨特異能，有時候我只想生成普通的農夫或商人。關鍵字輸入功能很好，但預設應該要是『無』。」
  - *AI 實作*：重構特質引擎，預設生成平民凡人（無超常異能）；當使用者輸入「火焰」、「霜凍」、「靈魂」等關鍵字時，才動態賦予相應的特質與規則效果。
- **轉折點 C：等級關鍵字解析與特殊狀態（被封印的大魔導師）**
  - *使用者提出*：「角色等級需要能自由輸入關鍵字，例如『大魔導師』必然有 12~16 等；甚至支援進階客製，例如『被封印的大魔導師』，等級在但部分法術環位遭到封印限制。」
  - *AI 實作*：開發自然語言等級解析器，將「老兵」對應至 Lv.5、「大魔導師」對應至 Lv.14，並在識別出「封印 / 詛咒」時，自動標記高環法術位限制警示。
- **轉折點 D：非典型武器與生活化法器（草耙與煙斗）**
  - *使用者回饋*：「如果我是農夫但戰鬥定位是戰士，武器可能是長草耙；法師可能不用魔杖，而是抽煙斗施法。」
  - *AI 實作*：建立「非典型敘事武器庫」與「故事奧術法器庫」，在戰鬥數據上精確映射至 D&D 5E 規則傷害骰（長草耙對應 1d8/1d10 多用武器、剁刀對應輕型揮砍、老煙斗對應專注法器），完美實現「故事外貌生活化，戰鬥數值規格化」。

### 階段 3：Excel 模板深度審查與資料欄位對齊
- 使用者上傳了包含 10 個工作表的大型 TRPG 角色卡 Excel 模板。
- AI 針對模板進行了結構化拆解：
  - 釐清了中文名詞標準：`體質` 在卡片中為 `體魄 (CON)`；`洞察` 為 `察言觀色 (Insight)`；`知覺` 為 `察覺 / 被動觀察 (Perception)`；`邪術師` 為 `契術師 (Warlock)`。
  - 完成了 `get_flattened_dict_for_excel()` 扁平化介面，將 40+ 項複雜物件資料精準轉換為鍵值對，確保日後與 Excel / CSV 欄位 100% 精準對接。

## 🛠️ 三、 技術實作與除錯過程 (Errors & Fixes)

在開發與測試階段，雙方排查並解決了以下工程挑戰：

1. **環境安全與無外網限制相依性**：
   - 考量到展示環境可能處於無網路或受限沙盒，本專案捨棄了重量級第三方套件（如 `openpyxl`），改用 Python 3 內建的 `json`、`csv`、`argparse`、`random`、`sys` 等標準模組，達成 **零外部安裝相依（Zero Dependency）**，即開即用。
2. **Windows 終端機編碼錯誤 (CP950 vs UTF-8)**：
   - Windows PowerShell 預設編碼常為 CP950，導致輸出 Emoji（📜、🎲、⚔️）時拋出 `UnicodeEncodeError`。
   - 解法：在 CLI 入口點 `main.py` 加入 `sys.stdout.reconfigure(encoding="utf-8", errors="replace")`，確保在任何 Windows 繁中終端機皆能完美渲染。
3. **直向快速掃視角色卡排版優化 (Vertical Quick-Scan)**：
   - 解決傳統橫向試算表在快速跑團時查閱不便的痛點，以 Markdown 直向條列式輸出：身分外貌 ➜ 擲骰建議 ➜ 非典型裝備 ➜ 等級特長 ➜ 劇本線索，讓 DM 在 3 秒內掌握 NPC 全貌。
