🤖 AI 協同開發歷程摘要 (AI Collaboration Summary)

專題題目：D&D 5E 劇情導向非典型 NPC 智慧生成系統 (TRPG Story-Driven Unorthodox NPC Generator)
開發環境：Python 3.12（純標準函式庫，零外部依賴，支援跨平台與 Windows UTF-8）
協同對象：人類開發者 (User / DM) × Google DeepMind Antigravity AI 系統
開源倉儲：https://github.com/41154B003Sam/dnd-5e-npc-generator

📌 一、 專題緣起與核心痛點定位

在 TRPG（桌上角色扮演遊戲，以《龍與地下城》D&D 5E 體系為核心）的跑團實務中，地下城主（DM / Storyteller）經常面臨龐大的即興備戰壓力：

  • 傳統開卡工具僵化：現有工具（如 D&D Beyond）多為玩家角色（PC）設計，強制遵循嚴格的配點限制、負重與技能套路，無法靈活對應劇本情境。
  • 缺乏故事溫度與非典型特色：傳統工具產出的戰士千篇一律是重甲劍盾；法師必定手持魔杖。但在精彩劇本中，往往需要「表面是麥農、手拿鋼草耙，真實身分卻是退隱禁衛隊長的戰士」，或是「抽著刻印符文的石楠木老煙斗施法的大魔導師」。
  • 規則限制玩家，而非約束 DM：使用者明確指出，規則是用來維護玩家平衡性，但 NPC 是 DM 鋪陳劇情的資產，應當具備更高的敘事自由度與非傳統彈性。
  • 多頁試算表翻找不易：大型 Excel 角色卡往往包含多達 10~19 個工作表，DM 在戰鬥與對話的緊湊節奏下，需要的是「垂直排列、一眼掃視全局」的直向卡片。

🔄 二、 人機深度對話與架構演進歷程 (六大關鍵轉折)

1. 轉折點 A：屬性點數不應硬編碼，改為「建議配置」與「種族加值候選清單」

使用者糾正：「屬性點數不需要直接寫死在卡片上。我們提供建議配置即可，種族加值也是列出可提升的清單，讓 DM 在需要時自主挑選，保留彈性。」

AI 實作：將屬性模組重構為「原始擲骰池（6 組 4d6dl1 明細）」+「職業最優建議配置（優先權建議）」+「獨立列出可選種族加值」，維持純粹建議性，不剝奪玩家與 DM 決策權。

2. 轉折點 B：非典型特長應支援「無」，隨心生成常規凡人

使用者糾正：「不是每個角色都需要獨特異能，有時候我只想生成普通的農夫或商人。關鍵字輸入功能很好，但預設應該要是『無』。」

AI 實作：重構特質引擎，預設生成平民凡人（無超常異能）；當使用者輸入「火焰」、「霜凍」、「靈魂」等關鍵字時，才動態賦予相應的特質與規則效果。

3. 轉折點 C：等級關鍵字解析與特殊狀態（被封印的大魔導師）

使用者提出：「角色等級需要能自由輸入關鍵字，例如『大魔導師』必然有 12~16 等；甚至支援進階客製，例如『被封印的大魔導師』，等級在但部分法術環位遭到封印限制。」

AI 實作：開發自然語言等級解析器，將「老兵」對應至 Lv.5、「大魔導師」對應至 Lv.13~14，並在識別出「封印 / 詛咒」時，自動標記高環法術位限制警示與 CR 戰力下修評估。

4. 轉折點 D：非典型武器與生活化法器（草耙與老煙斗）

使用者回饋：「如果我是農夫但戰鬥定位是戰士，武器可能是長草耙；法師可能不用魔杖，而是抽煙斗施法。」

AI 實作：建立「非典型敘事武器庫」與「故事奧術法器庫」，在戰鬥數據上精確映射至 D&D 5E 規則傷害骰（長草耙對應 1d8/1d10 多用武器、老煙斗對應專注法器），完美實現「故事外貌生活化，戰鬥數值規格化」。

5. 轉折點 E：從命令列進化到雙重零門檻圖形介面 (GUI & Web) 與 Windows 批次檔除錯

使用者提出：「要開終端機執行對我不夠友善... 另外點了 .bat 檔會閃退並出現『命令語法不正確』。」

AI 實作與底層排查：打造 Tkinter 原生桌面視窗 (gui.py) 與暗黑奇幻網頁版 (index.html)；排查 Windows cmd.exe 在繁中 CP950 下因 Unix LF 換行引發之解析崩潰，重構為 CRLF 規範，轉義 D^&D 5E，並加入跨目錄路徑自適應機制。

6. 轉折點 F：Excel 模板回填實驗、架構反思與最終回歸核心

使用者決策：「回填 Excel 模板導致格式損毀、許多下拉選單壞掉、部分圖片遺失。我決定放棄填入 Excel，因為破壞公式的問題無法根本解決。原本的網頁與應用程式版本已經相當優秀，回歸生成器本身。」

AI 架構收斂：第三方試算表庫在解析 19 個工作表的大型模板時極易丟失 VML 繪圖與破壞公式。系統果斷策略性回歸核心——以直向快速掃視角色卡 (Vertical Quick-Scan Card) 解決跑團真痛點，並提供可在 Excel/Google Sheets 純淨開啟且絕不毀損的通用 CSV 與相容 Roll20/Foundry VTT 的結構化 JSON 匯出，達成 100% 穩定與秒速生成。

🛠️ 三、 技術實作亮點與除錯彙整

工程挑戰 根本原因 具體解決方案
Windows 終端 Emoji 編碼錯誤 Windows 預設 CP950 編碼無法輸出 UTF-8 Emoji (📜, 🎲) 在 CLI 入口加入 sys.stdout.reconfigure(encoding="utf-8", errors="replace")。
批次檔閃退與語法錯誤 Unix LF 換行破壞 cmd 解析器；& 符號未轉義 批次檔強制使用 CRLF 換行，轉義 D^&D 5E，並加入 pause 與路徑回退機制。
零相依性離線環境 大型套件於無外網受限環境容易缺失 捨棄非必要第三方套件，全系統純以 Python 3 標準函式庫開發。
跑團主持資訊過載 傳統試算表橫向維度過大、翻頁繁瑣 設計 Markdown 直向排版，以高對比卡片在 3 秒內提供戰鬥與社交關鍵情報。

核心結論：本專題的成功展現了現代 AI 輔助軟體開發的典範——人類開發者具備敏銳的使用者體驗洞察力與關鍵架構決斷力；AI 助理則提供強大的模組實作力、跨平台相容性調校與文件標準化能力。透過敏捷的人機對話迭代，最終打造出這套兼具敘事溫度與規則嚴謹性的 D&D 5E 智慧生成系統。
